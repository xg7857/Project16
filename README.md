# 과제 16: 순차 탐색과 이진 탐색의 성능 비교

## 1. 실행 방법
```
gcc -O2 -o search_compare search_compare.c
./search_compare dataset_id_ascending.csv              # 예시 이름(Liam, Ryan, Nobody) 검색 + K 실험
./search_compare dataset_id_ascending.csv Emma Noah    # 원하는 이름 검색 + K 실험
```
- 학생 수 n = 32,033명, 서로 다른 이름 20,735개 → 동명이인이 많음(최대 9명).
- 퀵 정렬은 세 원소 중앙값 피벗 + Hoare 분할을 사용했습니다.
- 이름이 같을 때는 학번으로 순서를 정해(정수 비교, 이름 비교 횟수에 미포함) 동명이인이 항상 학번순으로 정렬됩니다. 덕분에 두 방법의 출력 순서까지 동일하며, 프로그램이 매 검색마다 두 결과가 일치하는지 검증합니다.
- 순차 탐색은 동명이인을 모두 찾기 위해 매번 배열 끝까지 비교하므로 검색 1회당 정확히 n회입니다. 이진 탐색은 하나를 찾은 뒤 좌우로 확장하며 확인하는 추가 비교도 모두 포함했습니다.

## 2. 검색 횟수 K 설정 이유
- **시작값 K = 1**: 검색이 한 번뿐일 때 정렬 비용이 얼마나 낭비인지 보기 위해.
- **촘촘한 구간 (5 단위, 이후 10 단위)**: 이론상 역전 지점이 K ≈ 20 근처로 예상되어 K = 5~50 구간을 세밀하게 관찰.
- **최댓값 K = 20,000**: 이후 점점 넓은 간격(100, 200, 500, …, 20,000)으로 키워, 역전 이후 격차가 얼마나 벌어지는지 확인. 20,000회면 순차 탐색 비용이 약 6.4억 회로 충분히 큼.
- 검색 목록은 고정 시드로 만든 하나의 목록(존재하는 이름과 존재하지 않는 이름을 번갈아 배치)이며, 작은 K의 목록은 큰 K 목록의 앞부분입니다(기존 목록에 새 검색을 추가하는 방식).

## 4. 분석

**K 증가에 따른 변화.** 순차 탐색은 검색 1회마다 항상 n = 32,033회를 쓰므로 총 비교 횟수가 K에 정확히 비례합니다(K=20,000에서 약 6.4억 회). 반면 퀵 정렬 + 이진 탐색은 처음에 682,031회라는 큰 고정 비용을 한 번 치르고 나면 검색 1회당 평균 약 15.7회(≈ log₂ 32,033 ≈ 15 + 동명이인 확인 비교)만 추가됩니다. 그래서 K가 1에서 20,000으로 2만 배 늘어도 이진 쪽 총합은 68만 → 약 99.5만으로 1.5배도 늘지 않습니다.

**역전 구간과 원인.** 실험에서 K = 21까지는 순차 탐색이 유리했고(Seq 672,693 < Bin 682,360), **K = 22부터 이진 방식이 유리**해졌습니다(Seq 704,726 > Bin 682,375). 원인은 두 방식의 비용 구조 차이입니다. 역전 시점은 대략 `정렬 비용 ÷ (n − 검색당 이진 비용) = 682,031 ÷ (32,033 − 15.7) ≈ 21.3`으로 계산되며, 실험값과 일치합니다. 즉 "정렬 비용 ≈ 순차 탐색 약 21회분"이므로, 같은 데이터를 21번 넘게 검색할 때부터 정렬이 이득입니다. 역전 이후에는 격차가 빠르게 벌어져 K = 1,000에서 순차가 이진의 약 46배, K = 20,000에서 약 650배의 비교를 사용합니다.

**장단점 (정렬 비용 고려).**

| | 순차 탐색 | 퀵 정렬 + 이진 탐색 |
|---|---|---|
| 장점 | 사전 준비 없음, 구현이 단순, 데이터가 정렬돼 있지 않아도 됨, 검색이 적을 때 가장 저렴 | 검색당 비용이 O(log n)으로 매우 작아 검색이 많을수록 압도적으로 유리 |
| 단점 | 검색마다 O(n)이라 검색이 많아지면 비용이 선형으로 폭증 | 초기 정렬 비용(약 68만 회)이 커서 검색이 적으면 손해, 정렬된 복사본 저장 공간 추가, 데이터가 바뀌면 재정렬/유지 비용 발생 |

**결론.** 검색이 몇 번 안 되는 일회성 조회(K ≤ 21)에는 순차 탐색이, 같은 데이터를 반복해서 검색하는 경우(K ≥ 22)에는 한 번 정렬해 두고 이진 탐색을 쓰는 편이 전체 비용 면에서 유리합니다. 초기 정렬 비용은 K가 커질수록 검색당 몫이 줄어들어(K = 20,000에서 검색당 약 34회분) 전체 성능에 미치는 영향이 사라지고, 결국 검색 효율의 차이(n vs log n)가 전체 성능을 결정합니다. 다만 이 결과는 비교 횟수 기준이며, 실제 실행시간에서는 정렬 중 데이터 이동 비용 등이 추가되므로 역전 시점이 다소 달라질 수 있습니다.
